# Drill #14 — 새의 비행 애니메이션

제공된 `bird_animation.png`를 활용해 새 10마리가 좌우로 반복 비행합니다.
LEC16의 게임 프레임워크와 프레임 시간을 바탕으로 구현했습니다.

## 실행

저장소 폴더에서 다음을 실행합니다.

```sh
python -m pip install -r Drill14/requirements.txt
python Drill14/main.py
```

기존 LEC16의 캐릭터·공·잔디·눈금자·시간 표시를 유지한 1600×600 화면에 새 10마리를 추가했습니다.
방향키로 캐릭터를 이동하고 Space로 공을 발사합니다. 수면 중 Space는 먼저 캐릭터를 깨웁니다.
새는 자동 비행하며, ESC 또는 창 닫기로 종료합니다.

## 구현 원리

- 원본 이미지 크기는 918×506이며, 5열×3행 중 마지막 칸은 비어 있습니다.
  왼쪽에서 오른쪽, 위에서 아래 순서로 유효한 14개 동작만 사용합니다.
- 원본의 간격이 완전히 균일하지 않아, 투명한 구간을 기준으로 열 경계
  `(0, 184, 367, 545, 727, 918)`과 행 경계 `(0, 170, 345, 506)`을 지정했습니다.
  이를 통해 옆 동작의 날개나 위 동작의 발이 함께 잘리는 문제를 방지했습니다.
- 이미지 좌표의 위쪽 기준 행을 Pico2D의 아래쪽 기준 좌표로 변환합니다.
- 날갯짓은 초당 2주기, 주기당 14프레임입니다.
  `frame = (frame + 28 × frame_time) % 14`로 계산하고, 출력할 때 정수로 변환합니다.
- 10픽셀을 30cm로 보고 기본 비행 속도 20km/h를 약 185.19픽셀/초로 환산했습니다.
  이동 거리는 `speed × frame_time`입니다. 개체마다 속도를 조금씩 다르게 설정했습니다.
- 새의 반 너비를 고려한 화면 양 끝 사이를 왕복합니다. 이동 거리를 왕복 거리로
  나눈 나머지로 위치와 방향을 구하므로, 긴 프레임에 여러 번 벽을 지나도 정상 처리됩니다.
- 왼쪽으로 날 때 이미지를 수평 반전해 부리가 이동 방향을 향하도록 했습니다.
- 10마리의 높이, 시작 위치, 방향, 애니메이션 시작 프레임을 다르게 설정했습니다.
  새 이미지 한 장은 모든 개체가 공유합니다.
- 기존 LEC16의 강제 지연 실습 `delay(0.1)`도 유지했습니다. 약 10 FPS 환경에서도 새의 이동과 날갯짓은 경과 시간을 기준으로 계산됩니다.

## 검증

- 10·30·60·144 FPS에서 8초 경과 후 위치, 방향, 애니메이션 진행량 비교
- 긴 프레임에서 여러 차례 경계를 넘는 경우 화면 내 위치 유지 확인
- 14개 프레임을 양방향으로 렌더링하고 빈 15번째 칸 제외 확인
- 새 10마리 생성, SDL 화면 출력 및 ESC 종료 시 객체 정리 확인

AI를 활용해 구현과 검증을 진행했습니다. 원본 이미지와 게임 프레임워크는 수업 자료를 기반으로 합니다.
